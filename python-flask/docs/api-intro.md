# Как устроен API

Базовый путь — `/api/v1`. Версия в пути, а не в заголовке: она видна
в журналах прокси, в метриках и в кеше, а значит, поддаётся разбору без
дополнительных инструментов.

Машинное описание: `/api/v1/openapi.json`, просмотр — `/api/v1/docs`.
Документ собирается из таблицы маршрутов при старте, поэтому он не может
описать несуществующий маршрут и не может пропустить существующий.

## Аутентификация

```http
Authorization: Bearer <access_token>
```

Пара токенов выдаётся `POST /api/v1/auth/login`. Токен доступа живёт
15 минут и не проверяется по базе. Токен обновления живёт 30 дней,
хранится в виде хеша и отзывается мгновенно; при каждом обновлении он
меняется. Повторное предъявление уже использованного токена обновления
считается признаком кражи и отзывает все сессии пользователя.

## Форма ответа

Успешный ответ — объект. Список верхним уровнем не отдаётся: к нему потом
некуда добавить метаданные постранично, не сломав клиентов.

```json
{
  "items": [ ... ],
  "meta": { "total": 128, "page": 2, "per_page": 20 }
}
```

Ошибка — всегда один и тот же объект:

```json
{
  "error": {
    "code": "booking_overlap",
    "message": "Экземпляр занят до 2026-03-05T14:00:00+03:00",
    "request_id": "8f2c1e...",
    "details": [ { "field": "starts_at", "code": "invalid_value", "message": "..." } ]
  }
}
```

Клиент разбирает `code`, а не `message`: сообщение может измениться,
код — нет. `request_id` совпадает с заголовком `X-Request-Id` и позволяет
найти запрос в журнале.

## Коды состояния

| Код | Когда |
| --- | --- |
| 200 | успешное чтение или изменение |
| 201 | ресурс создан; в `Location` — путь к нему |
| 202 | работа принята, но не выполнена (импорт) |
| 204 | успех без тела (выход, смена пароля) |
| 400 | запрос не прошёл проверку схемы |
| 401 | токена нет или он недействителен |
| 403 | прав недостаточно |
| 404 | не найдено — в том числе чужой объект |
| 409 | конфликт состояния: пересечение, недопустимый переход |
| 422 | правило предметной области нарушено |
| 429 | слишком часто; в `Retry-After` — через сколько повторять |
| 503 | зависимость недоступна; повтор осмыслен |

Различие 409 и 422 существенно: 409 означает, что состояние ресурса
несовместимо с операцией (бронь уже отменена), 422 — что данные
корректны по форме, но нарушают правило (срок больше 30 суток).

## Денежные суммы

Приходят и уходят строками: `"3500.00"`. Число с плавающей точкой в JSON
теряет копейки ещё до разбора, и `0.1 + 0.2` там не равно `0.3`.

## Время

Только с указанием смещения: `2026-03-01T10:00:00+03:00`. Значение без
смещения отклоняется с ошибкой проверки — молча трактовать его как
локальное значит получить расхождение в часы, а на границе суток — другой
тариф.

## Повторы запросов

Изменяющие операции принимают заголовок `Idempotency-Key`. Повтор с тем
же ключом в течение 24 часов возвращает сохранённый ответ, а не создаёт
второй объект. Тот же ключ с другим телом — ошибка `idempotency_key_reused`:
это не повтор, а другой запрос.
