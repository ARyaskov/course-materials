# Правила миграций

1. Каждая миграция применима к схеме, с которой работает предыдущая версия кода.
2. Удаление и переименование колонок — минимум два релиза.
3. `SET NOT NULL` — только после того, как значения заполнены отдельным релизом.
4. Индексы на таблицах свыше 100 000 строк — `CONCURRENTLY` и `$withinTransaction = false`.
5. `ALTER TABLE` начинается с `SET lock_timeout = '3s'`.
6. Перенос данных — задача очереди, не миграция.
7. `down()` либо работает, либо бросает `RuntimeException` с объяснением.
8. Перед релизом: `migrate --pretend` и резервная копия.
9. Опасная операция помечается комментарием `@safe-migration` с обоснованием.
