# Сетевой протокол nestor

Текстовый заголовок, двоичное тело. Ключи и значения — произвольные байты,
включая нулевые и переводы строк, поэтому длины указаны явно.

Разделитель строк — `\r\n`. Заголовочная строка не длиннее 64 байт.

## Запросы

```
PING\r\n
STATS\r\n
QUIT\r\n
GET <key_len>\r\n<key><CRLF>
DEL <key_len>\r\n<key><CRLF>
PUT <key_len> <value_len>\r\n<key><value><CRLF>
```

Глагол регистронезависим. `key_len` строго больше нуля; `value_len` может
быть нулевым — пустое значение это значение, а не отсутствие ключа.

## Ответы

```
+OK\r\n                    успех PUT, DEL, QUIT
+PONG\r\n                  ответ на PING
$<len>\r\n<bytes>\r\n      значение (GET, STATS)
$-1\r\n                    ключа нет
-ERR <текст>\r\n           ошибка
```

Ответы приходят в порядке запросов, поэтому клиент может слать команды
пачкой, не дожидаясь ответа на каждую (конвейеризация). Сервер разбирает
входной буфер до конца и складывает все ответы в выходной.

## Пример сессии

```
> PUT 9 14\r\nuser:1024{"tier":"pro"}\r\n
< +OK\r\n
> GET 9\r\nuser:1024\r\n
< $14\r\n{"tier":"pro"}\r\n
> DEL 9\r\nuser:1024\r\n
< +OK\r\n
> GET 9\r\nuser:1024\r\n
< $-1\r\n
```

## Ошибки и закрытие

Протокольная ошибка (неизвестный глагол, нечисловая длина, отсутствующий
`CRLF` после тела) необратима: сервер отправляет `-ERR`, дописывает
выходной буфер и закрывает соединение. Восстанавливать синхронизацию по
потоку, в котором длины уже не сходятся, нельзя.

Слишком длинная заголовочная строка и превышение лимитов на ключ или
значение обрабатываются так же — до того, как сервер начнёт выделять
память под тело.

Если выходной буфер соединения превысил `max_out_buffer`, соединение
закрывается: клиент, который шлёт запросы и не читает ответы, не должен
съедать память сервера.
