# Формат данных на диске

Всё кодируется явно, little-endian. Структуры C на диск не пишутся: их
раскладка зависит от компилятора, выравнивания и флагов сборки.

## Каталог базы

```
data/
  LOCK           файл эксклюзивной блокировки (flock), внутри pid держателя
  000001.data    сегмент данных
  000001.hint    снимок индекса сегмента (необязателен)
  000002.data    ...
```

Сегмент с наибольшим номером — активный: только в него идёт дозапись.
Остальные неизменяемы. Номера выдаются монотонно и не переиспользуются.

## Заголовок сегмента — 32 байта

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0  | 8 | магия `4E 53 54 53 45 47 00 01` (`NSTSEG\0\x01`) |
| 8  | 4 | версия формата (сейчас 1) |
| 12 | 4 | флаги, зарезервировано, 0 |
| 16 | 8 | номер файла |
| 24 | 8 | время создания, мс от эпохи |

## Запись — 28 байт заголовка плюс ключ и значение

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0  | 4 | CRC32C байтов 4..конца записи |
| 4  | 1 | флаги: бит 0 — надгробие |
| 5  | 1 | зарезервировано, 0 |
| 6  | 2 | длина ключа (1..65535) |
| 8  | 4 | длина значения (0..64 МиБ) |
| 12 | 8 | номер версии `seq`, монотонный в пределах базы |
| 20 | 8 | время записи, мс от эпохи |
| 28 | key_len | ключ |
| 28+key_len | value_len | значение |

Надгробие — запись с флагом `0b0000'0001` и нулевой длиной значения.

CRC покрывает всё, кроме самой суммы. Этого достаточно, чтобы отличить
целую запись от обрубленной при падении и от повреждённой на носителе.
CRC не защищает от злонамеренной подмены: это контроль целостности,
а не подпись.

## Hint-файл

Тот же 32-байтный заголовок с магией `NSTHNT\0\x01`, дальше записи:

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0  | 8 | смещение записи в `.data` |
| 8  | 4 | полная длина записи |
| 12 | 8 | `seq` |
| 20 | 2 | длина ключа |
| 22 | 1 | флаги |
| 23 | 1 | зарезервировано |
| 24 | key_len | ключ |

Hint-файл — ускоритель старта, а не источник истины. Если его нет или он
повреждён, индекс восстанавливается полным проходом по `.data`.

## Восстановление после сбоя

1. Сегменты открываются по возрастанию номера.
2. Для неактивных сначала пробуется hint-файл.
3. Активный сегмент читается целиком: записи применяются к индексу,
   пока встречаются корректные заголовки и сходится CRC.
4. Первая некорректная запись считается началом «оборванного хвоста».
   Хвост усекается `ftruncate`, дальше дозапись идёт с чистого места.
5. Побеждает запись с большим `seq`; надгробие удаляет ключ из индекса.

Поэтому порядок обхода сегментов не влияет на итог: `seq` задаёт
единственный правильный порядок версий.

## Совместимость

Версия формата хранится в заголовке каждого файла. Чтение файла с иной
версией — ошибка `NST_E_UNSUPPORTED`, а не попытка угадать раскладку.
Новые поля добавляются только увеличением версии.
