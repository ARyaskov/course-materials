# Результаты замеров

> **Числа в таблицах не заполнены намеренно.** Их нужно получить прогоном на
> конкретной карте: результат зависит от архитектуры, версии драйвера,
> состояния питания и температуры. Придуманные числа хуже отсутствующих —
> по ним принимают решения.

## Как получить числа

```bash
./scripts/ci.sh                      # сборка, тесты, бенчмарки, сравнение
./build/bench_stride                 # пропускная способность при разном шаге
./build/bench_distance               # полный перебор: block size x dim
./build/bench_topk                   # алгоритмы top-k
./build/bench_p2p                    # обмен между картами и с хостом
./build/bench_end_to_end             # полный цикл и QPS
```

Перед замером:

* закрыть остальные задачи на карте (`nvidia-smi` должен показывать 0% и
  минимальное потребление памяти);
* дать карте прогреться — первые прогоны идут на пониженных частотах;
* проверить троттлинг: `veclens monitor` или `nvidia-smi -q -d PERFORMANCE`.
  Замер при активном троттлинге сравнивать не с чем.

## 1. Пропускная способность при разном шаге (`bench_stride`)

Полезные байты считаются как `count * 4`. Реально из памяти читается сектор
32 байта, поэтому доля пика падает — это и есть цена некоалесированного
доступа.

| Шаг, элементов | ГБ/с | Доля пика, % |
|---|---|---|
| 1 | | |
| 2 | | |
| 4 | | |
| 8 | | |
| 16 | | |
| 32 | | |

Ожидаемая форма: при шаге 8 (32 байта) доля пика близка к 1/8 от шага 1,
дальше падение выходит на плато.

## Базовая линия для CI

`scripts/ci.sh` сравнивает текущий прогон с `bench/baseline.json` и падает
при замедлении больше 10%. Чтобы зафиксировать текущее состояние как базовое:

```bash
./scripts/ci.sh SKIP_SANITIZERS=1
cp build-ci/ci-artifacts/current.json bench/baseline.json
```

Базовая линия привязана к карте: `bench_report.py` предупреждает, если
`device` в файлах различается.
