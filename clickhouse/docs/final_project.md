# Финальный проект: аналитическое хранилище событий

Задание, критерии приёмки и соответствие этапов файлам репозитория-образца (глава 20).

## Задание

Веб-сервис с подпиской. Восемь вопросов с требованиями к свежести:

| Вопрос | Форма ответа | Свежесть | Механизм в образце |
| --- | --- | --- | --- |
| активность DAU/WAU/MAU | ряд по дням | минута | `events_hourly_users` (состояния) |
| удержание по когортам | когорта × неделя | час | `retention_weekly` (обновляемое) |
| воронка view → click → purchase | уровни по дням | минута | запрос по событиям с параметрами |
| ошибки и задержки по endpoint-ам | часы × группы | минута | `endpoint_hourly` |
| выручка по тарифам и странам | таблица с итогами | минута | `events_hourly` + колонка `plan` |
| похожие на купивших | список с расстоянием | сутки | `user_behavior_vectors` |
| хронология пользователя | строки за 90 дней | секунды | проекция `p_by_user` |
| разбор сессии | строки сессии | секунды | индекс `idx_session` |

Требования: событие видно ≤ 10 с; панели p95 ≤ 1 с; события 90 дней (30 горячих); витрины 2 года; сырьё 3 дня; логи 14 дней; архив бессрочно; ежедневные копии; роли с минимальными правами; европейские аналитики — только свои страны; панель здоровья, оповещения, руководства.

Ограничения: один сервер ClickHouse 26.3 + MinIO; расписания — средствами базы; всё воспроизводимо из репозитория за 10 минут; пароли — заглушки, секреты — в `.env`.

## Критерии приёмки (по проверкам, не по описанию)

**Схема.** `EXPLAIN` восьми запросов: чтение по ключу или витрине; TTL и партиции на каждой таблице; `EXCEPT` схем `events`/`events_staging` пуст; DDL применяется дважды без ошибок.

**Загрузка.** Кусков/мин — единицы при трёх входах; повтор пакета с токеном — 1 строка; JSON без обязательных полей — в сырье, не в событиях; задержка через брокер p50 в секундах; ведомость файлов идемпотентна; переразбор часа проходит.

**Запросы и витрины.** Восемь запросов с заголовками (период, пояс, точность, пороги) и параметрами; инварианты — 0 расхождений; сверка каждой витрины за час; backfill месяца; обновляемые представления без ошибок; план хронологии с проекцией; таблица стоимости с тремя столбцами.

**Оптимизации.** Индексы с оценкой локальности и сокращением чтения; планы дашборда без `Join`; попадание в кэш; `queries/regression_checks.sql` проходит.

**Доступ и наблюдаемость.** `queries/ch17_access_checks.sql` под каждым пользователем — ожидаемые коды; аудит содержит отказ входа и отказ доступа; расследование по `request_id` через логи и спаны; `pulse.incidents` получает строку при мелких вставках.

**Эксплуатация.** Копия сделана, восстановление отрепетировано и время записано; три аварии пройдены по `docs/runbooks.md`; настройки сервера с причинами; чистый стенд поднимается по README за измеренное время.

## Шкала

Пять блоков по 20 баллов: схема; загрузка; запросы и витрины; доступ и наблюдаемость; эксплуатация и воспроизводимость. Балл — за проверку с записанным числом. Журнал решений читается целиком: решение без альтернативы — вопрос на защите.

## Необязательные расширения

Мини-кластер с реплицируемой базой (`cluster/`), брокер как второй вход, настоящая модель для векторов (`ingestion/embed_messages.py`), движок временных рядов и PromQL.
