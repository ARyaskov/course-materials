# Список перед продакшеном

Пункт отмечается только с проверкой (команда или запрос), датой и именем. Дата старше квартала — проверить заново.

## Схема и хранение

| Пункт | Проверка | Дата | Кто |
| --- | --- | --- | --- |
| ключ сортировки под главные запросы | `EXPLAIN indexes = 1` восьми запросов дашборда/поддержки | | |
| партиции под срок хранения | `system.parts`: партиций на таблицу — десятки, не тысячи | | |
| TTL на каждой таблице | `system.tables` — `engine_full LIKE '%TTL%'` для всех MergeTree | | |
| политика хранения с холодным томом | `system.storage_policies`; куски старше 30 дней на `s3_cache` | | |
| staging повторяет схему событий | `EXCEPT` по `system.columns` пуст (`scripts/check.sh`) | | |
| определения совпадают с репозиторием | `SHOW CREATE` против `ddl/*.sql` | | |

## Загрузка

| Пункт | Проверка | Дата | Кто |
| --- | --- | --- | --- |
| пакеты или асинхронная вставка у каждого источника | `system.query_log`: средний `written_rows` вставки ≥ 1000 | | |
| токены идемпотентности и дедупликация блоков | повтор пакета → 1 строка | | |
| сырьё для внешних источников | `raw_events` наполняется; битый JSON остаётся в сырье | | |
| ошибки потока в отдельной таблице | `events_kafka_errors` | | |
| переразбор отрепетирован | `ingestion/backfill_views.sql` / staging + REPLACE PARTITION | | |
| кусков в минуту — единицы | `system.part_log` NewPart по минутам | | |
| задержка доставки измерена | p50/p99 `received_at - event_time` | | |
