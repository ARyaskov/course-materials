# ledger-cli

Итоговый проект курса «Scala для начинающих: язык и функциональное мышление».
Консольная утилита читает операции из учебного CSV, возвращает ошибки строк как
значения, считает сводку по завершённым операциям и выводит её в консоль или файл.

## Окружение и запуск

Версии закреплены: Scala **3.8.3**, sbt **1.12.9**, MUnit **1.3.1**.
Рекомендуемая JVM — JDK 21 или новее. Установленная команда `sbt` загрузит версию
из `project/build.properties`; команды выполняются из каталога `scala`.

```bash
sbt "run sample-data/transactions.csv"
sbt "run sample-data/transactions.csv --output report.txt"
sbt "run --help"
sbt test
sbt scalafmtCheckAll scalafmtSbtCheck
```

Через Scala CLI (современная команда `scala` или эквивалентная `scala-cli`):

```bash
scala run . -- sample-data/transactions.csv
scala run . -- sample-data/transactions.csv --output report.txt
scala test .
```

Директивы `project.scala` задают ту же Scala, зависимость тестов и параметры
компилятора, что и `build.sbt`. Файл с отчётом создаётся или перезаписывается
только после успешной проверки документа. Каталог назначения должен существовать.
Путь отчёта не может совпадать с входным файлом, включая существующую ссылку
на тот же файл. Для незнакомого содержимого используйте новый путь назначения.

## Контракт входного файла

Текст — UTF-8. Первая строка строго `id,category,amount,status`;
перед ней допускается UTF-8 BOM. Заголовок обязателен и не пропускается вслепую.
Данные могут отсутствовать: один заголовок — допустимый пустой набор.

Каждая непустая строка содержит ровно четыре поля:

| Поле | Правило |
| --- | --- |
| `id` | Непустой идентификатор, уникальный среди корректных строк документа |
| `category` | Непустое название категории, регистр сохраняется |
| `amount` | Положительное десятичное число, разбирается прямо в `BigDecimal`; границы описаны ниже |
| `status` | `completed`, `pending` или `failed`, без учёта регистра |

Пробелы вокруг полей удаляются. Все суммы считаются в одной денежной единице.
Пустые строки игнорируются, но сообщения содержат исходный физический номер
строки. Пустое последнее поле сохраняется и проверяется как пустой статус.

Для суммы допускается точка и научная запись (`1e3`). После удаления пробелов
поле ограничено 256 символами, число — 128 значащими цифрами и масштабом
от −128 до 128 (`BigDecimal.scale`). Например, `1e128` и `1e-128` допустимы,
а `1e2147483647` отклоняется как ошибка строки. Эти учебные границы ограничивают
расход памяти при арифметике и выводе десятичной записи; значения не округляются
для попадания в диапазон.

Это намеренно ограниченный учебный CSV: кавычки, запятые внутри полей и
многострочные поля не поддерживаются. Строка с кавычками отклоняется; обычный
`split` не выдаётся за полноценный CSV-парсер. Для сложного CSV нужна отдельная
библиотека и другой контракт входа.

## Как различаются ошибки

`ValidationError` описывает одну некорректную строку: неверное число полей,
пустой ID/категория, кавычки, нечисловая, слишком большая по точности/масштабу
или неположительная сумма, неизвестный
статус. Возвращается первая причина в порядке проверок; другие строки продолжают
обрабатываться. Корректные `pending`/`failed` сохраняются как данные, но не входят
в денежную сводку.

`DocumentError` относится ко всему документу: нет заголовка, неверный заголовок
или повторные ID. Дубли проверяются до отбора статусов; разные версии одного ID
не объединяются и не удаляются молча. При дублях отчёт не строится, а уже найденные
ошибки строк сохраняются в диагностике.

| Сценарий | Код процесса | stdout | stderr |
| --- | --- | --- | --- |
| Отчёт сформирован | 0 | Таблица или подтверждение записи файла | Ошибки отдельных строк, если есть |
| Справка | 0 | Инструкция запуска | Пусто |
| Ошибка чтения/записи или документа | 1 | Пусто | Причина отказа |
| Неверные аргументы | 2 | Пусто | Причина и инструкция запуска |

В файл записывается только отчёт, диагностика остаётся в stderr. Поэтому отчёт
с ошибочными строками может быть успешно построен: код 0 не означает, что каждая
строка входа была корректной. Нулевую сумму вместо повреждённой не подставляем.

## Проверяемый результат

`sample-data/transactions.csv` содержит 9 записей: 6 корректных и 3 ошибочных.
Из корректных 5 имеют статус `completed`, одна — `pending`.
Ожидаемый порядок и суммы:

```text
entertainment  2  85.00
groceries      2  60.50
transport      1  12.50
ИТОГО          5 158.00
```

Точный вывод сохранён в `sample-data/expected-report.txt`, диагностика — в
`sample-data/expected-errors.txt`. Повреждены физические строки 3, 4 и 10.
Дополнительные примеры: `invalid-header.csv`, `duplicates.csv`, `empty-data.csv`.

Сортировка сводки — сумма по убыванию, при равенстве название по возрастанию.
Деньги не проходят через `Double`. При печати показывается минимум два знака
после точки; дополнительная точность не округляется скрыто.

## Структура и границы

```text
project.scala                    # настройки Scala CLI
build.sbt                        # настройки sbt, MUnit, строгие предупреждения
project/build.properties         # совместимая версия sbt
project/plugins.sbt              # sbt-scalafmt
.scalafmt.conf                   # engine 3.11.5, dialect scala3
.github/workflows/ci.yml          # проверка форматирования и тестов
sample-data/                     # входные примеры и ожидаемый вывод
src/main/scala/ledger/
  model.scala                    # RawRecord, Transaction, Status
  errors.scala                   # ValidationError, DocumentError и render
  Parsing.scala                  # строка -> Either[ValidationError, Transaction]
  Pipeline.scala                 # документ -> Either[DocumentError, ProcessingResult]
  Aggregation.scala              # завершённые операции -> суммы категорий
  Report.scala                   # сводка -> текст
  Csv.scala                      # файловый ввод-вывод в UTF-8
  Cli.scala                      # аргументы -> Either[String, CliRequest]
  Application.scala              # сборка приложения -> RunResult
  Main.scala                     # печать и код завершения процесса
src/test/scala/ledger/           # MUnit: парсинг, агрегация, документ, отчёт, CLI/I/O
```

`Pipeline.process` — чистое ядро: его можно проверить обычным списком строк.
`Application.execute` выполняет файловые операции, но возвращает `RunResult`
вместо вызова `sys.exit`, поэтому тесты проверяют код и оба потока как данные.
Только `Main.scala` печатает и завершает JVM. Ресурсы чтения закрываются через
`Using`, строки материализуются до закрытия файла.

Весь документ загружается в память. Это проект для небольших файлов, а не
потоковый обработчик больших выгрузок. Операция записи отчёта не является
транзакционной публикацией файла; автоматические повторы и отмена фоновых задач
не реализованы.

## Проверки и форматирование

```bash
sbt test
sbt scalafmtAll scalafmtSbt
sbt scalafmtCheckAll scalafmtSbtCheck test
```

Компиляция включает `-deprecation`, `-feature`, `-unchecked`, `-Werror`.
Scalafmt engine 3.11.5 и sbt-plugin 2.6.1 закреплены отдельно. Этот plugin требует
sbt 1.12.9 или новее, поэтому прежняя версия sbt 1.10.7 обновлена.

Файл `.github/workflows/ci.yml` остаётся внутри урока как шаблон для самостоятельного
репозитория с содержимым каталога `scala` в корне. В общем репозитории учебных
материалов этот workflow не запускается; проверки выполняются командами выше
из каталога `scala`.
